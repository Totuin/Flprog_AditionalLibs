# Flprog_AditionalLibs — специализированные контроллеры FLProg

Версия библиотеки: **1.0.1 (кандидат, ожидает компиляцию в FLProg)**.

> **ВНИМАНИЕ.** Библиотека управляет логическими командами тестера аккумуляторов и промышленной последовательностью движения / зажима / подачи детали. Автономные тесты **не подтверждают безопасность оборудования**. Перед использованием на механизме необходима проверка электросхем, аварийных блокировок, концевиков, защит аккумулятора, работы при пропадании питания и временных параметров.

## Состав

| Файл | Назначение |
|---|---|
| `src/batteryTester.h/.cpp` | `FlprogBatteryTester` — цикл начальный заряд → разряд → окончательный заряд, а также ручные режимы |
| `src/sharicAuto.h/.cpp` | `FlprogSharicAuto` — последовательность поиска нуля, зажима, подачи и позиционирования двигателя |
| `examples/*_DryRun` | Примеры **без управления GPIO** для проверки подключения и API |
| `tests/` | Автономные тесты C++11 и заглушки Arduino / FLProg |
| `keywords.txt` | Подсветка типов, методов и констант Arduino IDE |

**Зависимости:** `Flprog_Utilites` (таймерные проверки) и `Flprog_StepMotor` (коды режимов/статусов двигателя). Используемые значения макросов сохранены. RT_HW и другие библиотеки не модифицированы.

## Тестер аккумуляторов

- `setCurrent(int16_t)` — ток в мА, может быть отрицательным;
- `setVoltage(int16_t)` и `setEndDischargeVoltage(int16_t)` — милливольты;
- `setEndChargeCurrent(int16_t)` — конечный ток заряда в мА;
- `setEndChargeTime(uint32_t)` — время подтверждения окончания заряда, мс;
- `pusk()`, `stop()`, `handCharge()`, `handDischarge()` — команды, применяются при последующем `pool()`;
- `setPolarityReversal(true)` — запрос остановки при обнаружении переполюсовки;
- `getMainRelayStatus()` и `getChangeoverRelayStatus()` — **логические запросы**, не физическое состояние реле;
- `getRawResidualCapacity()` — интегратор в мА·с, накопление в разряде примерно раз в 1000 мс;
- `getResidualCapacity()` — целая часть мА·ч (`raw / 3600`);
- `getErrorCode()` — диагностический код последнего `pool()` (0 — нет, 1 — нет тока в заряде, 2 — нет напряжения при разряде).

Значение интегратора насыщается на `UINT32_MAX` вместо переполнения в ноль. Если вызовы `pool()` редки, интегрирование за пропущенные секунды **не выполняется**, что влияет на точность расчёта ёмкости. Формат и единицы сырого счётчика не менялись.

**Известное ограничение:** диагностические коды `1`/`2` **сами по себе не выключают реле** — такова исходная логика. Не считать её достаточной защитой аккумулятора. В автомате также есть фиксированное ожидание 60 секунд после достижения порога разряда.

## Автомат Sharic

Используются `pusk()`, `stop()`, `setWorkMode()` и периодический `pool()`. Внешний код передаёт показания датчиков и статус двигателя и читает команды (`getCurrentMotorMode()`, `getCurrentTargetMotorPosition()`, `getCurrentMotorSpeed()`, `get*OutputStatus()`).

**Исправление 1.0.1:** `stop()` повторяемо сбрасывает все четыре логических исполнительных выхода и требуемую скорость двигателя. Это изменение поведения обязательно проверить на стенде без исполнительных механизмов, затем на аппаратно защищённом оборудовании.

**Незакрытые вопросы:** `setPermissionMoveRight()` и `setPermissionMoveLeft()` сохраняют флаги, но автомат их не проверяет; ожидание датчиков зажима не имеет тайм-аута; проверка направления движений использует сравнения координат, специфичные для конкретного станка; статусы двигателя, полученные извне, должны быть актуальными. Нельзя использовать эти средства как единственную систему безопасности.

**Совместимость:** буква `С` в `setStartSlotСutterPosition`, `setEndSlotСutterSpeed` и одноимённых идентификаторах — **кириллическая `С`**, не латинская `C`. Имя сохранено, чтобы не ломать существующий сгенерированный FLProg код.

## Проверка

Сначала открыть примеры `BatteryTester_DryRun` и `SharicAuto_DryRun`: они выводят только диагностические данные в `Serial` и не назначают физические пины. Для запуска автономных проверок в Linux/macOS: `sh tests/run_tests.sh` (GCC + ASan/UBSan); тесты также запускались с Clang. В Arduino IDE использовать настоящие зависимости FLProg.

Текущий статус — **компиляция C++11 на заглушках PASS**, реальная компиляция Arduino/FLProg ожидается. Подробнее — `AUDIT_FLPROG.md` и `CHANGELOG_FLPROG.md`.
